## 2. 目录结构规范（支持百级资产水平扩展）

工程直接建在仓库根目录，保留 `prototype/` 作为像素级视觉基线（在 TypeScript 与 ESLint 中排除）。`src/` 按职责划分为 6 个大区：

```text
UIFino/
├── prototype/                        # 历史 HTML 原型基线（只读对照）
├── docs/                             # 设计、架构、路线图、模块归档与评审记录
└── src/
    ├── middleware.ts                 # next-intl 多语言路径识别与重定向中间件
    ├── app/                          # 1. 路由装配层（仅做薄装配，不堆放业务逻辑）
    │   ├── layout.tsx                # 根壳层
    │   ├── [locale]/                 # 双语子路径 (/zh/..., /en/...)
    │   │   ├── layout.tsx            # 字体、主题、多语言上下文与全局 Toast
    │   │   ├── not-found.tsx         # 多语言 404 页面
    │   │   ├── (site)/               # 主站分组（含公告条、吸顶导航、悬停大菜单、⌘K、页脚）
    │   │   │   ├── layout.tsx
    │   │   │   ├── page.tsx          # 首页
    │   │   │   ├── catalog/          # 设计图鉴列表与 [slug] 品牌详情
    │   │   │   ├── components/       # 组件库一级总览、[category] 分类列表、[category]/[slug] 三栏工作台
    │   │   │   ├── templates/        # 整站模板目录与 [slug] 模板详情
    │   │   │   ├── tools/            # 工具入口与 [studio] 参数实验室（background / shadow）
    │   │   │   └── mcp/              # MCP 接入配置与智能检索沙盒
    │   │   └── (canvas)/             # 纯净画布分组（无顶底栏，供真实视口 iframe 隔离预览）
    │   │       └── preview/
    │   └── api/                      # 预留服务端接口目录
    ├── registry/                     # 2. 自包含资产注册表（一资产一目录，支持百级规模零冲突扩展）
    │   ├── catalog/                  # websites/<brand>/ 与 apps/<app>/ 独立目录 + _taxonomy.ts + index.ts
    │   ├── components/               # sections/ · blocks/ · pages/ · motion/ -> <category>/<slug>/ 三级目录
    │   ├── templates/                # <template-slug>/ 独立模板资产目录
    │   ├── tools/                    # background/ 与 shadow/ 预设库
    │   └── mcp/                      # clients/ 各编辑器接入配置与能力清单
    ├── core/                         # 3. 纯逻辑引擎层（零 React 依赖，按领域拆子包并就近配 __tests__/）
    │   ├── tokens/                   # 圆角、密度、品牌色板合成与 tokens.css 序列化
    │   ├── design-md/                # uifino/design-md@1.0 协议 YAML 头与章节编译器
    │   ├── codegen/                  # 虚拟文件树与 adapters/{react,vue,svelte,solid} 四框架生成器
    │   ├── studios/                  # background/（网格/点阵/极光/噪点）与 shadow/（多层阴影/顶光）数学换算
    │   └── search/                   # ⌘K 全站索引打分与 MCP 多维检索匹配引擎
    ├── components/                   # 4. 跨频道公共 UI 层
    │   ├── primitives/               # 原子组件（button, badge, segmented, tabs, popover, dialog, slider, select, input）
    │   ├── patterns/                 # 组合模式（page-banner, code-viewer, filter-bar, viewport-frame, token-swatch, state-views）
    │   └── shell/                    # 全局壳层（announce-bar, site-header, mega-menu, cmdk-palette, token-customizer, site-footer）
    ├── features/                     # 5. 频道业务模块层（home, catalog, library, templates, tools, mcp 内部再按区块拆目录）
    ├── i18n/                         # 6. 多语言路由与按频道分片的词条库（messages/{zh,en}/*.json）
    ├── stores/                       # Zustand 持久化状态（workbench-preset.store.ts, shell-ui.store.ts）
    ├── hooks/                        # 通用交互 Hooks（剪贴板、文件下载、快捷键）
    ├── lib/                          # 基础设施薄封装（cn.ts, fonts.ts, shiki.ts）
    └── styles/                       # 分层样式令牌（tokens/dark.css, tokens/light.css, tokens/typography.css, utilities/surfaces.css, globals.css）
```

## 3. 工程规范与远程门禁

1. **编译器严格模式**：`tsconfig.json` 强制开启 `"strict": true`、`"noUncheckedIndexedAccess": true`、`"noImplicitOverride": true`，排除 `prototype/` 目录。
2. **换行与编码规范**：全仓统一 UTF-8 编码与 LF 换行（通过 `.gitattributes` 锁定）。
3. **统一门禁命令**：`package.json` 提供一键门禁 `pnpm gate`（依次执行 `pnpm typecheck` 静态类型检查、`pnpm lint` ESLint 检查、`pnpm test` Vitest 核心单测、`pnpm build` Next.js 生产构建）。
4. **计算资源隔离**：依赖安装、门禁验证与 `next dev` 开发服务器全部通过 Git 同步至内网 `cicd mac (192.168.0.68)` 的 `~/remote-work/UIFino` 运行，本机通过 SSH 本地端口转发（`http://localhost:3000`）访问与截图验收。

## 4. 测试策略

- **必测范围**：仅对 `src/core/` 下的纯业务逻辑编写 Vitest 单元测试，覆盖：
  1. `core/tokens`：圆角、密度、品牌色板在亮/暗模式下的令牌解析与回退规则；
  2. `core/design-md`：YAML Frontmatter 与 Markdown 正文协议编译完整性；
  3. `core/codegen`：React、Vue、Svelte、Solid 四种框架代码与虚拟文件列表生成；
  4. `core/studios`：背景四引擎（网格/点阵/极光/噪点）与多层阴影的 CSS / Tailwind 输出；
  5. `core/search`：全局命令搜索过滤与 MCP 多维条件检索匹配。
- **免测范围**：路由页面、接口胶水、多语言词条文案、纯 UI 展示组件（配色、布局、间距、外观）一律不写单测，通过生产构建门禁与真实浏览器多视口走查验收。

## 5. 关键决策

1. **采用根目录单工程 + 预留 Workspace 演进**：当前聚焦将前端原型做扎实，直接建在根目录路径最清晰；保留 `prototype/` 原目录不入编译范围，随时可做像素对比。
2. **采用 `/[locale]/...` 显式语言子路径路由**：中文 `/zh/...` 与英文 `/en/...` 拥有独立规范网址，兼顾后续国内外搜索引擎收录与双语外链分享。
3. **资产层采用“一资产一文件夹”注册表模式（`src/registry/`）**：将未来会增长到数百个的品牌规范、组件与整站模板彻底从业务视图中剥离，新增资产只需添加独立子文件夹并在分类入口注册，杜绝单文件膨胀与并行开发冲突。
